线上缺陷能溜过去的原因。

## 本轮发现并修复的两个缺陷

### 一、打了卡星图看不出变化

**现象**：点亮第一枚星之后，旁边的星图完全没有变化。

**排查过程走过三次弯路**：先怀疑星点半径太小，再怀疑面板比例太扁，
还猜过 CSS 变量没定义。**每次都靠再量一次推翻自己**，最后量了星点的实际坐标才找到真因：

```
cx: "0.4487011671300892"      ← 坐标是 0~1 的小数
viewBox: "0 0 400 400"        ← 星图的坐标空间是 0~400
```

数据库里 `star.x / star.y` 存的是**归一化坐标（0..1）**，而星图组件按
**viewBox 单位（0..400）**来解释 —— **生产方与消费方的单位不一致**，
于是所有星点挤在左上角一个像素范围内，半个圆还落在面板外。

**为什么只有仪表盘不对、落地页那张却是好的**：落地页用的是 `demoConstellation()`，
它的数据本来就是 0~400。两处行为不一致这件事本身，就是「问题出在单位约定上、
而不是渲染」的证据。

**修复**：由组件导出 `MAP_VIEW_SIZE`，两个调用方显式相乘 ——
把一个隐含约定变成看得见的乘法。同时放大了星点、压暗了面板内的背景星野
（它和用户的星都是画点，全对比度会把用户那几颗彻底盖住）、把面板改成正方形。

**回归测试**：`interact` 现在断言星点必须落在面板内且散布跨度不退化。
单位再错一次会直接失败。

### 二、功能模块点击没反应

**现象**：网页展示的各项功能模块点击时大部分没有反应。

**根因**：那些卡片**根本不是可点的**。`FeatureCard` / `FeatureRow` /
`FeatureCarousel` 三个组件都没有 `href`，也没有 `onClick`，
`feature-carousel` 连 `"use client"` 都没有 —— 整页唯一能点的是两个 CTA、
一个锚点，外加一个指向 `https://github.com` 首页的**占位链接**。

**修复**：给 `FeatureCard` 加了可选的 `href`，三处调用都传 `/register`
（未登录时点功能页也会被弹回登录，直接给注册入口更顺；已登录时注册页自己会送到观测台）。
链接容器直接是 `flex-1` + flex 列，把原来的伸缩关系原样透传 ——
不能简单再包一层，否则卡片会塌、同一行的高度对齐与底座会错位。

**回归测试**：`interact` 断言 article 总数必须等于被 `<a>` 包裹的数量。

## 复现方式

```bash
# 单测 + 类型 + 风格
pnpm check

# 12 个页面的打开、文字、控制台、溢出
pnpm regress --email <账号> --password <密码> --handle <用户名>

# 链接去处、卡片可点、星图几何
pnpm interact --base https://deep-stars.onrender.com --email <账号> --password <密码>
```

跑线上时把 `--base` 换成对应地址即可；`regress` 用环境变量 `REGRESS_BASE`。
